## Diagnosis (corrected)
Historical data was migrated to the v2 `grid=h3/level=1/tile=…` layout on S3 (bulk-build `part_000000` files, years 1982–2026), legacy files were deleted, but the live `earthcatalog.db` still references the 4,473 legacy paths → every search touching history 404s. The catch-up's 7,349 v2 files and the 43.2M-key index are healthy.

## Steps

Expected: match → pure metadata fix.
2. **Safety.** Fresh backup of the current production db into `refactoring/backups/` (keeps the pre-catchup one too).
3. **Rebuild metadata.** Run `rebuild_iceberg_from_warehouse` (dual-layout; preserves table properties incl. grid/time-bin/index-path) over the production warehouse, register only files that exist, upload the rebuilt db.
4. **Validate.** Re-run the exact integration tests that failed (Greenland 2019/2024 queries — the ones that 404'd) plus spot searches per decade; confirm table rows ≈ 67.5M + 590k and searches return items.
5. **Resume go-live.** PR #2 merge (CI already green), first scheduled run tomorrow 14:00 UTC closes the Sep-6→8 delta.
